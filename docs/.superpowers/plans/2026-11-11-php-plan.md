# PHP im Code-Graphen, in der Prüfkette und in der Kompatibilitätsliste — Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PHP steht in Graph, Prüfkette und Kompatibilitätsliste auf der Stufe von Python, für PHP 8.2 bis 8.5. 8.6 läuft als Vorab-Probe.

**Architecture:**
- Extraktor `php` und Resolver `resolve/php.go` nach dem Muster von C#.
- Namespaces je Typ und Funktion in `Result.Enclosing`.
- Stack `php`, dessen Werkzeuge aus `vendor/bin` kommen.
- Laufzeit `php` mit den Release- und RC-Quellen von php.net.

**Tech Stack:** Go, gotreesitter v0.57.0 (`grammars/php`), Composer 2.11.2, PHPUnit 11.5.57, 12.5.43 und 13.4.6, PHPStan 2.3.5, PHP_CodeSniffer 4.0.4, Xdebug 3.5.3.

**Spec:** `docs/.superpowers/specs/2026-11-11-php-design.md` (Pins: Recherche, Nachtrag 2026-11-11)

  - TDD, 100 % Coverage je Funktion, kein `init()`

  - PHPStan 2.3.5, PHP_CodeSniffer 4.0.4
  - setup-php 2.40.0 = `eb7c497e18156a6bbabfef1d3a82760b9eda3962`
  - Xdebug 3.5.3

## Review Focus

1. **Mehrere `namespace`-Blöcke in einer Datei.** Jeder Typ trägt seinen
   eigenen Namespace. Test in Task 1.
2. **Unqualifizierter Funktionsaufruf.** Erst der eigene Namespace, dann der
   globale (PHP-Regel); eine Klasse fällt nie global zurück. Test in Task 2.
3. **Trait-Methode über `$this->m()`.** Die Kante führt auf den Trait. Test
   in Task 2.
4. **HTML-Teile in einer `.php`-Datei.** Kein Absturz, und der Code in
   `<?php … ?>` wird gelesen. Test in Task 1.
5. **Projekt ohne `vendor/`** (Werkzeuge nicht installiert). Die Lanes
   melden „nicht verfügbar“ statt rot. Test in Task 3.

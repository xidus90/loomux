# HTML, CSS und SCSS im Code-Graphen, mit Brücken zu JS, in der Prüfkette und in der Kompatibilitätsliste — Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** HTML, CSS und SCSS stehen im Graphen. Seiten, Stylesheets und Skripte sind über die vier Web-Brücken verbunden. Die Prüfkette lintet HTML mit html-validate und CSS/SCSS mit stylelint, nachgewiesen auf Node 22, 24 und 26.

**Architecture:**
- **Extraktoren:**
  - `extract/stylesheet` mit zwei Sprachen (`css`, `scss`)
  - `extract/html` bettet je Sprache einen Teil ein: JavaScript über `ecmascript.Part`, CSS über `stylesheet.Part`.
- **Resolver:** `resolve/web.go`, mit den Familien `html` und `stylesheet`.
- **Lesart der Verweise:** Alle Seitenverweise (`<script src>`, `<link href>`, `@import`, Stylesheet-Importe aus JS) liest eine Funktion, `pageRef`. Sie ruft `localPath`.
- **Scopes:** HTML und JS schreiben ihre Web-Übergaben als Rohkanten `references`/`calls` mit dem Namespace in `Member`. Der Scope entsteht erst im Resolver. Das schließt Lücke 7 und die Alias-Lücke aus dem ECMAScript-Ledger.
- **Prüfkette:** Die Stacks `html` und `css` gibt es schon. Sie bekommen:
  - gepinnte Werkzeuge
  - Dateilisten ohne `node_modules` und Build-Ausgaben
  - eine Vorgabe-Konfiguration für stylelint
  - graph und rules

**Tech Stack:** Go, gotreesitter v0.57.0 (`grammars/html`, `grammars/css`, `grammars/scss`); Werkzeuge: zuerst die installierten des Projekts, sonst gepinnt über `npx --yes`: html-validate 11.21.0, htmlhint 1.9.2 (Variante), stylelint 17.16.0, stylelint-config-standard-scss 17.0.0; Compat auf Node 22, 24, 26.

**Spec:** `docs/.superpowers/specs/2026-11-11-web-design.md` (Programm: `2026-11-10-graph-sprachen-programm.md`; Vorgänger: `docs/.superpowers/plans/2026-11-11-ecmascript-plan.md` mit Ledger `.superpowers/sdd/2026-11-11-ecmascript-plan/progress.md`)

   - `dist/`, `build/` und `*.min.css`

   Nichts davon kommt in den Graphen oder in die Dateilisten der Lint-Lanes. Tests in Task 2 und Task 6.
4. **Ein gemeinsames `app.js` auf zwei Seiten, die beide `id="app"` haben.**

  - SCSS: `@use` (`Kind "use"`, `Alias` = Namensraum: `as y` gibt `y`, `as *` gibt `*`, ohne `as` leer), `@forward` (`Kind "forward"`) und `@import` (`Kind "import"`, ein Import je String).

  - Ein ERROR-Knoten wird als Text gelesen.
  - `@use "x" as y` ergibt den Import und den Namensraum: `@use\s+["']([^"']+)["']\s+as\s+([\w-]+|\*)`.
  - `@extend` ergibt die Rohkante: `@extend\s+([%.][\w-]+)`.

# Rust im Code-Graphen, in der Prüfkette und an Godot (gdext) — Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rust steht in Graph, Prüfkette und Kompatibilitätsliste auf der Stufe von C++. Rust-Klassen aus gdext erreichen Godot über GDScript, Szenenknoten und Szenen-Verbindungen, und die GDScript-Suite läuft gegen die frisch gebaute Rust-Extension.

**Architecture:**
- Testmarkierung am Knoten (`model.Node.Test`) und Blast-Signal über Spans.
- Ein Tree-sitter-Extraktor `rust` mit Kopfregel, Makro-Heuristik und gdext-Attributen.
- `Cargo.toml` als Moduldatei neben `go.mod`/`tsconfig.json`; ein Resolver `resolve/rust.go` mit Modulbaum.
- Godot: `godot.class` aus dem Extraktor, `godot.method`/`godot.signal` aus dem Resolver; `check godot-suite` und `godot rescan` bauen die Extension.
- Prüfkette und Kompatibilität als Daten, Block-Marker im linecov-Profil `rust`.

**Tech Stack:** Go, gotreesitter v0.57.0 (`grammars/rust`, tree-sitter-rust v0.24.2), BurntSushi/toml (vorhanden), Rust stable 1.100.0, cargo-llvm-cov 0.9.1, crate `godot` 0.5.5, gdUnit4 6.2.2.

**Spec:** `docs/.superpowers/specs/2026-11-14-rust-design.md` (Muster: `2026-11-10-graph-sprachen-programm.md`, `2026-11-10-cpp-design.md`, `2026-11-10-graph-bruecken-design.md`)

## Global Constraints

- **TDD.** Jede Funktion hat 100 % Coverage, sonst `//coverage:exempt <Grund>` direkt über `func`.
- **Kein `init()`.** Keine Paketvariable, die eingebettete Daten parst.
- **Sprache.** Code, Kommentare und Commits englisch; Doku deutsch, außer unter `docs/en/`.
- **Kommentare.** Keine Historie im Code; steht eine Tatsache im Wiki, ein Satz und der Link.
- **Commits.** Conventional Commits, kein `Co-Authored-By`, nie pushen. Der Commit-Hook ist das Tor.
- **Wiki im selben Task.** Jeder Task, der Verhalten ändert, zieht `docs/wiki/topics/code-graph.md` bzw. die genannten Doku-Seiten und `docs/wiki/log.md` im selben Commit nach.
- **Sprachname und Version.** Sprache `rust`, Endung `.rs`, Version `rust/1`.
- **Node-IDs.** Methoden `rel#Typ.methode`, Inline-Module mit `::` (`rel#tests::adds`), Kollisionen über `extract.MintID`.
- **Feste Versionen.** `godot = "=0.5.5"` im Fixture, `cargo-llvm-cov` 0.9.1 in CI, Toolchain `1.100.0`; vor dem Pin frisch nachsehen (Regel aus CLAUDE.md), nur bei neuerer Version anheben.
- **Kein Schema-Bump.** `model.Node.Test` ist `omitempty`; `schemaVersion` bleibt 3.

## Review Focus

1. **`impl` in einer anderen Datei als der `struct`, mit `#[class(rename=X)]`.** Das Methoden-Angebot trägt `Class = X`, nicht den Rust-Namen. Test in Task 6.
2. **Zwei `impl Foo` in einer Datei mit gleichnamiger Methode (`fmt` aus zwei Traits).** Zwei Knoten (`Foo.fmt`, `Foo.fmt~2`), kein Absturz, Aufruf `x.fmt()` ohne Kante (nicht eindeutig). Tests in Task 2 und Task 6.
3. **`#[cfg(test)] mod tests` mit Hilfsfunktion außerhalb von `#[test]`.** Auch die Hilfsfunktion ist `Test`; eine Änderung nur am Testmodul macht das Blast-Signal der Produktivfunktion nicht „geändert“, eine Änderung an der Produktivfunktion allein ebenfalls nicht. Tests in Task 1 und Task 2.
4. **`use` mit Gruppen und Alias (`use crate::a::{b::{self, C as D}, *};`).** Jeder gebundene Name kommt einzeln an. Test in Task 3.
5. **`.gdextension` mit Schlüssel ohne Architektur und mit `editor`-Tag, beide auf `target/debug`.** `cargo build` läuft genau einmal. Test in Task 10.

# C++ im Code-Graphen, in der Prüfkette und an Godot — Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** C++ steht in Graph, Prüfkette und Kompatibilitätsliste auf der Stufe von Python. GDExtension-Klassen erreichen Godot über GDScript, Szenenknoten und Szenen-Verbindungen.

**Architecture:**
- Ein Tree-sitter-Extraktor `cpp` mit Makro-Maske und der Regel „eigener Teilbaum ohne ERROR“.
- Ein Resolver `resolve/cpp.go`.
- Ein Klassen-Scope im Brückenkern (`Export.Class`, `Bridge.Class`).
- Zwei neue Übergaben im GDScript-Resolver.
- Prüfkette und Kompatibilität als Daten.

**Tech Stack:** Go, gotreesitter v0.57.0 (`grammars/cpp`), CMake, GoogleTest 1.18.0, gcovr 8.8, clang-tidy und clang-format in CI.

**Spec:** `docs/.superpowers/specs/2026-11-10-cpp-design.md` (Programm: `2026-11-10-graph-sprachen-programm.md`, Recherche: `2026-11-10-graph-sprachen-recherche.md`)

## Global Constraints

- **TDD.** Jede Funktion hat 100 % Coverage, sonst `//coverage:exempt <Grund>` direkt über `func`.
- **Kein `init()`.** Keine Paketvariable, die eingebettete Daten parst.
- **Sprache.** Code, Kommentare und Commits sind englisch; Doku ist deutsch, außer unter `docs/en/`.
- **Kommentare.** Keine Historie im Code.
- **Commits.** Conventional Commits, kein `Co-Authored-By`, nie pushen. Der Commit-Hook ist das Tor.
- **Sprachname und Versionen.**
  - Sprache `cpp`, Version `cpp/1`. Die Endungen stehen in der Spec, ohne `.c`.
  - GDScript-Version `gdscript/7`.
- **Godot-Namen.**
  - IDs nutzen nur `.` als Trenner.
  - `Owner` ist nie ein Namespace. Der ganze Qualifier einer Methode außerhalb der Klasse steht in `Result.Enclosing`.
- **Feste Versionen.** Neue Fremdwerkzeuge werden exakt gepinnt: GoogleTest 1.18.0 (Tag und Hash im `FetchContent`), gcovr 8.8.

## Review Focus

1. **`TEST_F(S, N)` im Allman-Stil** (Klammer auf der nächsten Zeile). Er darf nicht maskiert werden. Test in Task 2.
2. **Methode einer kaputten Klasse unter einem ERROR.** Sie bekommt keinen erfundenen Owner. Test in Task 2.
3. **Gleicher Klassenname in zwei Namespaces und zwei Headern.** Die Methode außerhalb der Klasse findet die richtige über den Qualifier. Test in Task 4.
4. **Include-Endung mehrdeutig** (`include/a/x.h` und `src/a/x.h`). Keine falsche Kante. Test in Task 4.
5. **`if consteval` verschluckt die folgende Definition.** Der Test hält fest, wie weit der Schaden reicht. Task 2.

**Interfaces:**
- Produces: `cpp.Language{}` mit `Name "cpp"`, `Version "cpp/1@"+Parser`, den Endungen der Spec.
- Produces: Knoten und Owner nach der Spec. `Result.Enclosing` bekommt:
  - für Typen den Namespace (`a::b`, `""` global)
  - für Methoden außerhalb der Klasse den ganzen Qualifier (`ns::A::B`), zusammengesetzt aus umgebendem Namespace und Qualifier
- Produces: Rohkanten.
  - `imports` (`Specifier` = Include-Pfad wie geschrieben, `Alias` leer; System-Include mit `<>` markiert im Feld, das `extract.Import` dafür hat oder das hier dokumentiert neu entsteht)
  - `extends`
  - `calls`: Receiver `""`, `this` oder ein Qualifier mit `::`; `Member "new"` für `new T`
  - Bindungen mit `Relation references`, `Member "godot.method"`/`"godot.signal"`, `Specifier` = Godot-Name, Receiver = Klasse, Name = Methode (bei Signalen leer)
  - `extract.go` dokumentiert die neue Bedeutung von `Member`.
- Produces: `Exports` `godot.class <Name>` für jede Klasse mit `GDCLASS(<Name>, …)` im Rumpf; Ziel ist der Klassenknoten.
